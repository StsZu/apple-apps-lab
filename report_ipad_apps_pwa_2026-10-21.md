# Власні програми для iPad: розробка на MacBook Air за допомогою Claude Code

Дата перевірки: **21 жовтня 2026 року**.

Це перевірена й упорядкована редакція наданої розмови. Повтори, залишки карток зображень і неповні посилання видалено. Нижче наведено виправлення, практичні варіанти та джерела.

## 1. Висновок перевірки

**Основна рекомендація правильна:** для власних довідників, тренажерів, калькуляторів і нескладних облікових інструментів доцільно почати з PWA. Її можна створювати на MacBook Air за допомогою Claude Code та використовувати на iPad без членства в Apple Developer Program і без семиденного строку підпису.

Водночас PWA не гарантує автоматично офлайн-роботу, збереження даних назавжди, синхронізацію або всі можливості нативної програми. Ці властивості залежать від реалізації та браузера.

### Що виправлено й уточнено

| Теза у вихідному тексті | Уточнення |
| --- | --- |
| PWA дозволяє користуватися програмою «роками» | Немає строку дії підпису Apple, але потрібні підтримка сумісності, резервні копії та доступний сайт для завантаження й оновлень. |
| Додавання іконки означає готову PWA | Іконка сама по собі не забезпечує кешування та офлайн-роботу. |
| Локальний вебзастосунок — окрема технологія | Це спосіб розміщення. Такий застосунок теж може бути PWA. |
| Swift Playgrounds — спосіб отримати власну встановлену програму | Безкоштовно можна запускати проєкт усередині середовища Swift Playground. Це слід відрізняти від окремого встановлення застосунку через Xcode або App Store. |
| Для локальної PWA достатньо сервера в мережі | Для service worker потрібен захищений контекст, зазвичай HTTPS. VPN сам по собі не робить HTTP-адресу захищеним контекстом. |
| PWA на кількох пристроях працює з тими самими даними | IndexedDB локальна. Синхронізацію або обмін файлами потрібно реалізувати окремо. |
| GitHub Pages підходить для будь-якого застосунку | Це статичний хостинг. Власний серверний код, серверна база та захищене зберігання API-ключів потребують іншого компонента. |
| Автоматичні оновлення відбуваються одразу | Service worker може залишати попередню версію до активації оновлення. Потрібен продуманий механізм оновлення. |
| У PWA обмежений Bluetooth/USB | Для Safari на iPad не слід закладати пряме керування периферією через Web Bluetooth/WebUSB: ці API не підтримуються. Імпорт файлів із USB-носія через системний вибір файлів — інша можливість. |

## 2. Варіанти використання

| Варіант | Плата Apple за розробника | Семиденне перепідписування | Як запускається |
| --- | --- | --- | --- |
| PWA на HTTPS-сайті | Не потрібна | Ні | Через іконку вебзастосунку або браузер |
| Вебзастосунок на Mac/Raspberry Pi | Не потрібна | Ні | Через мережу; офлайн можливий лише за відповідної реалізації |
| Swift Playground на iPad | Для локальної роботи не потрібна | Не є схемою встановлення через Personal Team | Проєкт запускається у Swift Playground |
| SwiftUI + Xcode + Personal Team | Безкоштовно | Так | Окремий тестовий застосунок на пристрої |
| AltStore Classic із безкоштовним обліковим записом | Безкоштовний підпис Apple | Так; інструмент намагається автоматизувати оновлення | Окремий нативний застосунок |
| Apple Developer Program | Стандартно 99 USD на рік; перевіряйте місцеву ціну | Семиденне обмеження Personal Team не застосовується | Тестування та розповсюдження за обраною схемою |
| Альтернативне розповсюдження в ЄС | Залежить від умов розробника й каналу | Інша схема розповсюдження | Нативні застосунки за правилами Apple та магазину |

Це плата саме Apple. Claude Code, зовнішні AI API, сервер, домен або інші сервіси можуть мати окрему вартість. Платне членство також не означає довічної дії будь-якої тестової збірки. [1][2][8]

### Personal Team: що підтверджує Apple

Для безкоштовної Personal Team Apple вказує: до **10 App IDs**, до **3 пристроїв**, до **3 встановлених застосунків на пристрій**. App IDs, реєстрації пристроїв і provisioning profiles мають семиденні обмеження. Після завершення дії профілю застосунок потрібно повторно зібрати та встановити. [1]

Не потрібно попередньо видаляти програму: повторне встановлення збірки з тією самою ідентичністю зазвичай зберігає її дані. Для важливих даних усе одно потрібен експорт.

AltStore Classic не скасовує цей строк: якщо оновлення підпису не відбулося вчасно, застосунок не відкриється. SideStore та Sideloadly також не варто сприймати як спосіб отримати безстроковий безкоштовний підпис Personal Team. Конкретні вимоги їхніх актуальних версій потрібно перевіряти окремо. [1][8]

### Альтернативні магазини

Для iPad у ЄС потрібні відповідний регіон Apple Account і фізичне перебування в ЄС. Самого перебування в Україні або зміни регіону облікового запису недостатньо. Після виїзду Apple дозволяє користуватися встановленими застосунками, а оновлювати їх — до 90 днів; установлення нових залежить від регіональної відповідності. [9]

Альтернативний магазин не є універсальним способом установити власний довільний IPA без підпису. Apple передбачає нотаризацію та окремі умови розповсюдження. AltStore Classic і альтернативний магазин AltStore PAL — різні механізми. [8][9]

## 3. Що таке PWA

**PWA — Progressive Web App, прогресивний вебзастосунок.** Його інтерфейс і логіка виконуються браузерними технологіями: HTML, CSS і JavaScript. React і TypeScript можна використовувати для зручності розробки, але вони не є обов’язковими.

Типова схема для цього проєкту:

1. Claude Code допомагає писати код на MacBook Air.
2. Зібраний застосунок публікується на HTTPS-хостингу.
3. На iPad сайт відкривається в Safari й додається на початковий екран.
4. Локальна логіка виконується на iPad. Mac не повинен залишатися ввімкненим, якщо він не виконує роль потрібного застосунку сервера.

Для передбачуваної поведінки готують web app manifest з назвою, іконками, адресою запуску й режимом відображення. Service worker забезпечує керування кешем і може підтримувати офлайн-запуск. Це окремі частини реалізації. [3][4][5]

### Встановлення на iPad

1. Відкрити HTTPS-адресу застосунку в Safari.
2. Натиснути **«Поділитися»**.
3. За потреби відкрити **«Ще» / View More**, потім **«На початковий екран»**.
4. Якщо є перемикач **Open as Web App**, увімкнути його.
5. Натиснути **«Додати»**.

Назви пунктів залежать від мови й версії iPadOS. Іконку додають окремо на кожному пристрої. [3]

## 4. Можливості та межі PWA

| Можливість | Практичне пояснення |
| --- | --- |
| Форми, таблиці, графіки, пошук, тренажери | Добре підходять для PWA; конкретну швидкодію перевіряють на цільовому iPad. |
| Робота без інтернету | Потрібно заздалегідь завантажити й кешувати необхідні ресурси. Дані й функції, залежні від сервера, можуть бути недоступні. |
| Локальне зберігання | IndexedDB підходить для структурованих даних, але не є резервною копією. |
| Камера та QR-коди | Можливі з дозволом користувача. Для QR може знадобитися програмний декодер; не слід припускати наявність усіх API. |
| Імпорт та експорт файлів | Через доступні браузерні й системні діалоги; це не довільний доступ до файлової системи iPad. |
| Push-сповіщення | Для вебзастосунків на початковому екрані підтримуються з iPadOS 16.4; потрібні дозвіл і реалізація Web Push. Членство Apple Developer Program не потрібне. [4] |
| Фонові процеси | Не слід планувати безперервну роботу або точні довільні таймери в закритому застосунку. Service worker не є постійно запущеним сервером. [5] |
| Bluetooth та USB | Прямі Web Bluetooth/WebUSB не підходять для Safari на iPad. Для обладнання може знадобитися нативний застосунок або мережевий шлюз. [10] |
| Apple Pencil | Базове малювання можна реалізувати вебтехнологіями; спеціальні можливості й системні інтеграції потребують окремої перевірки. |
| Кілька пристроїв | Один код можна адаптувати для iPad, iPhone, Mac і Windows. Дані між ними автоматично не синхронізуються. |

### Збереження даних

WebKit використовує квоти та правила очищення сховища. Можна запитувати persistent storage через Storage API, але це не замінює резервного копіювання. Користувач може очистити дані; можливі й інші причини втрати доступу до них. [6]

Практичні вимоги: експорт та імпорт JSON, перевірка відновлення, обробка помилок запису і міграції формату даних. Зміну домену слід планувати як перенесення даних, оскільки браузерне сховище прив’язане до походження сайту.

## 5. Рекомендована архітектура

Це інженерна рекомендація для особистого інструмента, а не вимога Apple.

| Компонент | Вибір для першої версії |
| --- | --- |
| Розробка | Claude Code на MacBook Air |
| Інтерфейс | React + TypeScript; для малого інструмента достатньо звичайного JavaScript |
| Збирання | Vite |
| Дані | IndexedDB |
| Офлайн | Service worker + Cache API |
| Оформлення вебзастосунку | Manifest та іконки |
| Резервування | Експорт/імпорт JSON |
| Хостинг | GitHub Pages для статичної версії без секретів |
| Синхронізація | Окремий сервер або сервіс, тільки якщо потрібна |

### GitHub Pages: важливі умови

GitHub Pages розміщує статичні HTML/CSS/JavaScript. У GitHub Free він доступний для публічних репозиторіїв. Публікація інтерфейсу сама по собі не означає публікацію записів IndexedDB: вони залишаються на пристрої, якщо код їх нікуди не надсилає. [7]

Для адреси виду `https://USER.github.io/REPO/` потрібно узгодити Vite `base`, шляхи manifest, `start_url`, `scope` та service worker. Vite окремо документує налаштування `base` для GitHub Pages. [11]

Не вбудовуйте секретні API-ключі у фронтенд: JavaScript і конфігурація, доставлені браузеру, доступні користувачу. Для викликів платного AI API з секретним ключем потрібен захищений серверний компонент. Локальний облік може працювати офлайн, а функція звернення до хмарного ШІ — потребувати мережі.

### Сервер на Mac або Raspberry Pi

Такий сервер може обслуговувати інтерфейс, синхронізацію або роботу з обладнанням. Якщо функція залежить від сервера, він має бути доступним. Кешована автономна частина PWA може працювати без нього.

Для service worker використовуйте HTTPS із сертифікатом, якому довіряє iPad. Адреса `http://192.168.x.x` не отримує виняток `localhost`: на iPad `localhost` означає сам iPad. VPN захищає транспорт мережі, але не змінює вимоги браузера до захищеного контексту. [5]

## 6. Якщо потрібен SwiftUI

Нативний застосунок доцільний, якщо вимоги залежать від системних API, спеціального обладнання або інтеграцій, яких бракує вебплатформі. Нативні фонові можливості також мають обмеження iPadOS.

Для початку встановіть повний Xcode, відкрийте його та завершіть початкове налаштування. Потім перевірте в Terminal:

```bash
xcode-select -p
xcodebuild -version
xcrun simctl list devices available
```

Якщо активними є лише Command Line Tools, виберіть установлену версію Xcode в його налаштуваннях Locations. Відсутність симуляторів може означати, що відповідний runtime ще не завантажений.

Claude Code може підготувати SwiftUI-проєкт. Для запуску на фізичному iPad у Xcode додають Apple Account, обирають Personal Team, автоматичне підписування та пристрій. На iPad виконують запити довіри й увімкнення Developer Mode, якщо вони з’являються. Цей шлях залишається тестовим із семиденним строком. [1]

Swift Playground — додаткова можливість запускати сумісні SwiftUI-проєкти в самому середовищі на iPad. Не кожен проєкт Xcode можна перенести туди без адаптації. [12]

## 7. Завдання для першої PWA

Приклад промпту для Claude Code:

```text
Створи PWA MyTasks для особистого використання на iPad.

Використай React, TypeScript і Vite. Зроби український інтерфейс,
адаптивний для iPad у двох орієнтаціях, з підтримкою дотику й клавіатури.

Функції: додавання, редагування, виконання та видалення завдань.
Зберігай дані локально в IndexedDB. Додай експорт та імпорт JSON
з перевіркою структури файлу й обробку помилок запису.

Додай manifest, іконки та service worker. Після першого повного
завантаження основні функції мають працювати без інтернету.
Не використовуй зовнішні ресурси, необхідні для офлайн-запуску.

Підготуй конфігурацію для GitHub Pages з урахуванням назви репозиторію:
Vite base, manifest start_url/scope і шляхи service worker.
Зроби повідомлення про доступне оновлення та оновлення без втрати даних.
Не вбудовуй API-ключі чи інші секрети у клієнтський код.

Перевір production-збірку. Підготуй інструкцію встановлення в Safari
та перевірки на реальному iPad. Окремо вкажи, що перевірено автоматично,
а що потребує перевірки на пристрої.
```

### Критерії приймання

1. Збірка завершується без помилок.
2. Застосунок відкривається через іконку на iPad.
3. Після першого повного завантаження запускається в авіарежимі; додавання, редагування та видалення працюють.
4. Дані зберігаються після закриття й повторного запуску.
5. Експортований файл успішно імпортується з відновленням записів.
6. Нова опублікована версія встановлюється через механізм оновлення без втрати даних.
7. Інтерфейс перевірений у двох орієнтаціях на реальному iPad.

Це вимоги до майбутнього застосунку. У межах цього звіту застосунок не створювався і ці перевірки не виконувалися.
